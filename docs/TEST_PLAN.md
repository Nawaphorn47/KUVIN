# แผนทดสอบ KU VIN

เอกสารนี้แบ่งการทดสอบเป็น 3 ชั้น ผลของชั้นอัตโนมัติอยู่ที่ [test-report/README.md](test-report/README.md) (มีรูปหน้าจอ)

| ชั้น | ทดสอบอะไร | รันอย่างไร | ใครรัน |
|---|---|---|---|
| 1. ทดสอบหน่วย/บริการของ API | ตรรกะคิว, สมัคร/ล็อกอิน, OTP, ความปลอดภัย, แชต, ความปลอดภัยระหว่างทริป, การชำระเงิน | `npm run test:<ชื่อ>` ใน `apps/api` (ดู `.github/workflows/ci.yml`) | CI ทุกครั้งที่ push |
| 2. E2E อัตโนมัติผ่านเบราว์เซอร์จริง | ผู้ใช้จริงใช้งานครบ: สมัคร, เรียกวิน, รับงาน, แชต, จบทริป, จ่ายเงิน, ให้คะแนน, แอดมินอนุมัติ ฯลฯ | `cd e2e && npm test` | CI ทุกครั้งที่ push / นักพัฒนา |
| 3. ทดสอบมือบนอุปกรณ์จริง | สิ่งที่เครื่องอัตโนมัติจำลองไม่ได้ (ด้านล่าง) | ทำตามตารางข้อ 3 | คน |

## 1. ชุด E2E อัตโนมัติ (27 กรณี)

| ชุด | ไฟล์ | ครอบคลุม |
|---|---|---|
| 01 ระบบขึ้นครบ | `01-smoke` | `/health` (เช็ก DB), security headers, ค่าตั้งค่าแอป, Splash → ต้อนรับ → ล็อกอิน, หน้าแอดมิน, ลิงก์แชร์ที่ไม่ถูกต้อง |
| 02 ผู้โดยสาร | `02-passenger-auth` | สมัครด้วย OTP (โหมดทดสอบ), OTP ผิด, ขอซ้ำเร็วไป, เบอร์ไม่ครบ, ด่านเซลฟี่ก่อนเรียกครั้งแรก |
| 03 ทริปเต็ม | `03-full-trip` | **2 ผู้ใช้พร้อมกัน**: เรียกวิน → ข้อเสนอเข้าคนขับ → รับงาน → แชต 2 ทาง → เดินทาง → จบ → จ่ายเงินสด → ให้คะแนน → ตรวจฐานข้อมูล |
| 04 ความปลอดภัย | `04-safety-and-privacy` | แชร์ทริป (ไม่เห็นเบอร์/นามสกุล), ซ่อนเบอร์หลังจบทริป, แจ้งปัญหา + แอดมินเห็นเคส, เอกสารเป็นไฟล์ส่วนตัว, ไฟล์ปลอมถูกปฏิเสธ, สิทธิ์ข้ามบทบาท, ไม่มี token = 401 |
| 05 สมัครขับ | `05-driver-signup-and-admin` | เลือกประเภทนิสิต/วิน, เอกสารต่างกันตามประเภท, ฟอร์มไม่ครบกดไม่ได้, แอดมินตรวจเอกสาร/อนุมัติ/ปฏิเสธ + คนขับเห็นเหตุผล |

### วิธีรัน

```bash
docker compose up --build -d          # เปิด stack ในเครื่อง (ต้องมี .env: cp .env.example .env)
cd e2e && npm install && npx playwright install chromium
npm test                              # รันทั้งหมด (~40 วินาที)
npm run report:docs                   # สร้างรายงาน + รูปที่ docs/test-report
```

- รันเฉพาะไฟล์: `npx playwright test tests/03-full-trip.spec.js` · ดูแบบเห็นเบราว์เซอร์: `npm run test:headed`
- เทสต์ **สร้างข้อมูลทดสอบลงฐานข้อมูลจริง** จึงถูกกันไม่ให้ชี้ไป `kuvinn.tech` (ตั้ง `WEB_URL`/`API_URL` ไปที่ staging ได้เท่านั้น)
- stack ทดสอบตั้ง `AUTH_RATE_LIMIT_MAX=1000` เพื่อให้สมัคร/ล็อกอินซ้ำหลายรอบได้ — **บน production ห้ามตั้ง** (ค่าเริ่มต้น 20 ครั้ง/15 นาที/IP)

## 2. ข้อจำกัดของชั้นอัตโนมัติ (ตรงไปตรงมา)

- ใช้ Chromium จำลองมือถือและพิกัด GPS ที่กำหนดเอง **ไม่ใช่เครื่องจริง** (ไม่ครอบคลุม iPhone/Safari, Android WebView ของ APK)
- เซลฟี่/เอกสารเป็นไฟล์ภาพสีทึบที่สร้างเอง ไม่ได้ทดสอบกล้องจริง
- OTP เป็นโหมดทดสอบ (แอปโชว์รหัส) ยังไม่ได้ทดสอบ SMS จริงเพราะยังไม่ได้ซื้อบริการ
- ไม่ได้ทดสอบภาระ (load test) และความถูกต้องของตำแหน่ง GPS ระหว่างขับจริง
- **ไม่ใช่ผล UAT:** ผลนี้มาจากสคริปต์ ไม่ใช่ผู้ใช้จริง ห้ามนำไปรายงานเป็นผลประเมินความพึงพอใจ

## 4. เกณฑ์ผ่านก่อนส่งงาน
