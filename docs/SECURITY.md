# ความปลอดภัยของ KU VIN

เอกสารนี้สรุปมาตรการความปลอดภัยของระบบ แยกเป็นฝั่งซอฟต์แวร์ (ป้องกันระบบและข้อมูล) กับฝั่งผู้ใช้ (ป้องกันคนระหว่างเดินทาง)
และบันทึกสิ่งที่ยังทำไม่ได้พร้อมเหตุผล เพื่อใช้ในรายงานหัวข้อข้อจำกัดและงานต่อยอด

อัปเดตล่าสุด: 19 ต.ค. 2569

---

## 1. ฝั่งซอฟต์แวร์ — ทำแล้ว

### การยืนยันตัวตน

| มาตรการ | รายละเอียด | ทดสอบ |
|---|---|---|
| บัญชีเดียวสลับโหมด | ผู้โดยสาร/คนขับเป็นบัญชีเดียวกัน token แยกบทบาท (`user` / `driver`) สิทธิ์ของแต่ละ API ตรวจตามบทบาทเหมือนเดิม | `test:identity` |
| OTP เบอร์โทร | เก็บรหัสแบบ hash (sha256) ใช้ได้ครั้งเดียว หมดอายุ 5 นาที ผิดได้ 5 ครั้งต่อรหัส | `test:identity` |
| กันเดา OTP | ขอรหัสได้ไม่เกิน 5 ครั้ง/ชม./เบอร์, ขอซ้ำได้ทุก 30 วินาที, ผิดรวมทุกรหัส 10 ครั้ง = ล็อกเบอร์ 1 ชม. และมี rate limit ต่อ IP | `test:security` |
| OTP โหมดทดสอบบนเซิร์ฟเวอร์จริง | ให้รหัสเฉพาะเบอร์ใน `OTP_TEST_PHONES` เท่านั้น (ตั้ง `*` = ทุกเบอร์ ต้องตั้งใจเปิดเอง) | `test:security` |
| ผู้โดยสารยืนยันตัวตน | ต้องยืนยันเบอร์ด้วย OTP + ถ่ายเซลฟี่ ก่อนเรียกวินครั้งแรก เปลี่ยนเบอร์ = ต้องยืนยันใหม่ | `test:identity` |
| คนขับยืนยันตัวตน | แยก 3 ประเภท เอกสารต่างกัน (ดูตารางด้านล่าง) แอดมินพื้นที่ตรวจและอนุมัติก่อนรับงาน | `test:identity` |
| Google login | ตรวจ ID token กับ Google และเทียบ `aud` กับ `GOOGLE_CLIENT_ID` บัญชีใหม่ต้องยืนยันเบอร์ด้วย OTP ก่อน | – |
| ระงับบัญชี | ระงับแล้วตัดออกจากระบบทันที (REST + socket) ระงับบัญชีผู้ใช้ = โหมดคนขับที่ผูกไว้ถูกระงับด้วย | `test:suspension`, `test:security` |
| JWT secret | production ไม่ยอมเริ่ม server ถ้า `JWT_SECRET` ว่าง/เป็นค่าเริ่มต้น/สั้นกว่า 32 ตัวอักษร | `test:security` |

เอกสารคนขับแต่ละประเภท (คิวรับงานเดียวกันทุกประเภท):

| ประเภท | ข้อมูล | เอกสาร |
|---|---|---|
| นิสิต | รหัสนิสิต | รูปหน้าตรง, บัตรนิสิต, ใบขับขี่, รูปรถเต็มคัน, ป้ายทะเบียน |
| บุคคลทั่วไป | – | รูปหน้าตรง, บัตรประชาชน, ใบขับขี่, รูปรถเต็มคัน, ป้ายทะเบียน |
| วินมอเตอร์ไซค์ | เบอร์เสื้อวิน, ชื่อวินที่สังกัด | รูปหน้าตรง, บัตรประชาชน, ใบขับขี่สาธารณะ, รูปเสื้อวิน, ป้ายทะเบียน |

### ข้อมูลส่วนบุคคล (PDPA)

| มาตรการ | รายละเอียด |
|---|---|
| เอกสารเป็นไฟล์ส่วนตัว | บัตร/ใบขับขี่/เซลฟี่ เก็บใน `uploads-private/` ไม่เสิร์ฟสาธารณะ เปิดได้ผ่านลิงก์ที่เซ็นแล้วอายุ 15 นาทีเท่านั้น |
| เห็นเฉพาะคนที่มีสิทธิ์ | เอกสารคนขับ: เจ้าของ + แอดมินพื้นที่ / เซลฟี่ผู้โดยสาร: แอดมินพื้นที่เท่านั้น (คนขับไม่เห็น) |
| อ้างไฟล์คนอื่นไม่ได้ | ชื่อไฟล์ผูกกับเจ้าของ ส่ง URL ภายนอกหรือไฟล์ของคนอื่นมาแทนจะถูกปฏิเสธ |
| ตรวจเนื้อไฟล์ | ตรวจ magic bytes ว่าเป็น JPEG/PNG/WEBP จริง ไม่เชื่อชนิดไฟล์ที่ client แจ้ง ไม่ผ่าน = ลบทิ้ง |
| อัปโหลดสาธารณะ | เฉพาะแอดมิน (ใช้กับโลโก้พื้นที่) |

### ระบบทั่วไป

- CORS เปิดเฉพาะโดเมนของระบบ (`CORS_ORIGINS`)
- Security headers: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, HSTS เมื่อเป็น HTTPS
- จำกัดขนาด JSON ที่ส่งเข้า API 100 KB, ความคิดเห็นรีวิว ≤ 500 ตัวอักษร, ข้อความแชต ≤ 300 ตัวอักษร และ ≤ 200 ข้อความ/ทริป
- แชตในทริป: อ่านได้เฉพาะคู่กรณี ส่งได้เฉพาะระหว่างทริป เก็บไว้ให้ตรวจย้อนหลังเมื่อมีเรื่องร้องเรียน
- ผล SonarQube และการแก้ไข: ดู [SONARQUBE.md](SONARQUBE.md)

## 2. ฝั่งซอฟต์แวร์ — ยังทำไม่ได้ (ข้อจำกัด)

| เรื่อง | ทำไมยังทำไม่ได้ | ตอนนี้ใช้อะไรแทน | ทางแก้ในอนาคต |
|---|---|---|---|
| ส่ง OTP ทาง SMS จริง | ต้องซื้อบริการ SMS (มีค่าใช้จ่ายต่อข้อความ) | โหมดทดสอบ ให้รหัสเฉพาะเบอร์ทดสอบที่กำหนด | ต่อผู้ให้บริการ SMS ใน `sendSms()` แล้วตั้ง `OTP_MODE=sms` |
| ตรวจว่าเซลฟี่เป็นคนจริง (liveness) และตรงกับหน้าบัตร | ต้องใช้บริการ eKYC/face match ที่มีค่าใช้จ่าย | แอดมินตรวจด้วยตาเทียบรูปหน้าตรงกับบัตร | ต่อบริการ eKYC ตอนส่งเอกสาร |
| ตรวจบัตรประชาชนกับฐานข้อมูลรัฐ (DOPA) | ต้องได้รับอนุญาตเชื่อมต่อจากกรมการปกครอง | แอดมินตรวจรูปบัตร | ขอเชื่อมต่อผ่านผู้ให้บริการ eKYC ที่ได้รับอนุญาต |
| ตรวจประวัติอาชญากรรมคนขับ | ต้องยื่นตรวจกับหน่วยงานรัฐ ระบบตรวจเองไม่ได้ | – | ให้คนขับแนบหนังสือรับรองความประพฤติเป็นเอกสารบังคับ |
| ยืนยันสถานะนิสิตด้วย KU ALL Login | ต้องลงทะเบียนระบบกับสำนักบริการคอมพิวเตอร์ (OCS) ก่อน ไม่ทันกำหนดส่ง | แอดมินตรวจรูปบัตรนิสิต + รหัสนิสิต | ยื่นแบบฟอร์มกับ OCS แล้วต่อ OAuth (รองรับ PKCE) |

ยังทำได้ในโค้ดแต่ยังไม่ได้ทำ:

- **ยกเลิก token ตอนออกจากระบบ** — token อายุ 7 วัน ออกจากระบบแล้ว token เก่ายังใช้ได้จนหมดอายุ
- **ลบพิกัด GPS ในรูป (EXIF)** — รูปจากมือถืออาจมีพิกัดสถานที่ถ่ายติดมา
- **ย้ายเอกสารเก่า** — เอกสารคนขับที่อัปโหลดก่อนเปลี่ยนเป็นไฟล์ส่วนตัว ยังอยู่ในโฟลเดอร์สาธารณะ `uploads/`

## 3. ฝั่งผู้ใช้ — ความปลอดภัยระหว่างเดินทาง

### มีแล้ว

| ฟีเจอร์ | ช่วยอะไร |
|---|---|
| ยืนยันตัวตนทั้งสองฝ่าย | คนเรียกยืนยันเบอร์ + เซลฟี่ คนขับส่งเอกสารให้แอดมินตรวจ ทั้งสองฝั่งรู้ว่าอีกฝ่ายถูกตรวจแล้ว |
| ข้อมูลจับคู่รถตรงจุดรับ | หน้า "คนขับกำลังมา" โชว์เลขเสื้อวิน ป้ายทะเบียน รุ่นรถ ประเภทคนขับ และบอกให้ดูให้ตรงก่อนขึ้น |
| ปุ่ม SOS ทุกหน้าทริป | โทร 191 / 1669 / เบอร์ฉุกเฉินของพื้นที่ และแจ้งแอดมินพร้อมตำแหน่งและข้อมูลทริปทันที |
| แชตในแอป | คุยกันได้โดยไม่ต้องให้ไลน์ส่วนตัว เก็บประวัติไว้ตรวจย้อนหลัง มีคำเตือนห้ามส่ง OTP/เลขบัญชี |
| ติดตามคนขับสด | เห็นตำแหน่งคนขับบนแผนที่และเวลาที่จะถึง |
| ให้คะแนน + ฟีดแบ็ก | ผู้โดยสาร ↔ คนขับ ให้คะแนนกันได้ มีแท็กปัญหา เช่น ขับเร็วไป ไม่สุภาพ |
| ระงับบัญชี | แอดมินระงับคนที่มีปัญหาได้ทันที |
| **แชร์ทริปให้คนที่ไว้ใจ** | ผู้โดยสารส่งลิงก์ (อายุ 6 ชม.) ให้เพื่อน/ครอบครัวเปิดดูได้โดยไม่ต้องลงแอป เห็นชื่อเล่น รถคันไหน ตำแหน่งสด จบทริปแล้วไม่บอกตำแหน่งต่อ ไม่มีเบอร์โทร/นามสกุล |
| **ซ่อนเบอร์โทร** | เห็นเบอร์อีกฝ่ายเฉพาะตอนทริปกำลังดำเนินอยู่ ประวัติย้อนหลังและงานที่ถูกเสนอแต่ยังไม่รับไม่เห็นเบอร์ (กันโทรตามภายหลัง) |
| **แจ้งปัญหาหลังทริป** | ผู้โดยสาร/คนขับแจ้งได้ภายใน 7 วัน เลือกหมวด (ขับอันตราย, คุกคาม, เก็บเงินเกิน, ไม่จ่ายเงิน, ลืมของ ฯลฯ) ส่งเข้าแดชบอร์ดแอดมินพื้นที่แบบ real-time เคสด่วนขึ้นก่อน แอดมินปิดเคสพร้อมบันทึก |

ทดสอบ: `npm run test:trip-safety`

### ตัดสินใจไม่ทำ

| ฟีเจอร์ | เหตุผล | ใช้อะไรแทน |
|---|---|---|
| PIN ขึ้นรถ (ผู้โดยสารบอกรหัสให้คนขับกรอกก่อนเริ่มทริป) | ยุ่งยากเกินไปสำหรับทริปสั้นในพื้นที่ (ทดลองทำแล้วตัดออก) | ผู้โดยสารเช็กเลขเสื้อวิน ป้ายทะเบียน รุ่นรถในแอปก่อนขึ้น / คนขับทักชื่อผู้โดยสารก่อนออกตัว |

### เสนอเพิ่ม (ยังไม่ได้ทำ)

| ฟีเจอร์ | ช่วยอะไร | ความยาก |
|---|---|---|
| ไม่จับคู่กันอีก | ผู้โดยสาร/คนขับเลือกไม่ให้ระบบจับคู่กับคนนี้อีก | กลาง |
| เช็กความปลอดภัยอัตโนมัติ | ทริปนานเกินเวลาประมาณมาก ๆ หรือหยุดนิ่งนาน แอปถามว่า "โอเคไหม" พร้อมทางลัด SOS | กลาง |
| เตือนหมวกกันน็อก | เตือนคนขับเตรียมหมวกให้ผู้โดยสาร (กฎหมายบังคับทั้งคนขับและคนซ้อน) | ง่าย |
| คู่มือความปลอดภัย | หน้าแนะนำสั้น ๆ: เช็กป้าย/เสื้อ/หน้าก่อนขึ้น, ไม่ให้ OTP ใคร, ใช้ SOS เมื่อไหร่ | ง่าย |

## 4. เช็กลิสต์ก่อนเปิดใช้งานจริง

- [ ] ตั้ง `JWT_SECRET` เป็นค่าสุ่มยาว ≥ 32 ตัวอักษร
- [ ] ตั้ง `CORS_ORIGINS` เป็นโดเมนจริงของแอปและแดชบอร์ด
- [ ] เลือก OTP: ต่อ SMS จริง (`OTP_MODE=sms`) หรือโหมดทดสอบพร้อม `OTP_TEST_PHONES` เฉพาะเบอร์ผู้ทดสอบ
- [ ] ไม่ตั้ง `PASSENGER_VERIFICATION=off` บนเซิร์ฟเวอร์จริง
- [ ] สำรองโฟลเดอร์ `uploads-private/` (เอกสารยืนยันตัวตน) และจำกัดสิทธิ์เข้าถึงบนเซิร์ฟเวอร์
- [ ] ใส่เบอร์ฉุกเฉินของแต่ละพื้นที่ในหน้าแอดมิน
- [ ] ใช้ HTTPS เท่านั้น
